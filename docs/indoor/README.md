# Indoor home-map configuration

The caregiver can author one home's room graph in the authenticated dashboard,
save it on the Pi, download the versioned JSON document, and preview a shortest
room sequence using a manually selected starting room. The map and route preview
are configuration/demo tools:

- The selected starting room is demo input; it does not show the wearer's current location.
- It does not detect landmarks with the camera or localize a person.
- It does not provide directional or spoken guidance.
- It does not change the existing GPSD outdoor service.

The dashboard's live indoor status therefore remains
`unavailable / not_integrated`. A map file is not evidence of physical location.

## Data schema, version 1

```json
{
  "schema_version": 1,
  "map_id": "2eeaf8f8-a607-4f66-87d1-fb701504e5d7",
  "name": "Home",
  "rooms": [
    {"id": "7eb44b7a-b55c-46c5-8130-116130dfb343", "name": "Hall"},
    {"id": "02eaf8c4-5c0e-45bd-a113-e301d8f78a49", "name": "Kitchen"}
  ],
  "connections": [
    {
      "id": "fa0b0edb-5afd-44ca-829b-e2273b1499e2",
      "from_room_id": "7eb44b7a-b55c-46c5-8130-116130dfb343",
      "to_room_id": "02eaf8c4-5c0e-45bd-a113-e301d8f78a49",
      "kind": "doorway"
    }
  ],
  "landmarks": [
    {
      "id": "LM-HALL-1",
      "room_id": "7eb44b7a-b55c-46c5-8130-116130dfb343",
      "label": "Hall marker"
    }
  ]
}
```

`map_id`, room IDs, and connection IDs are canonical lowercase UUIDs. The
caregiver assigns a landmark ID; IDs are case-insensitively unique across the
map. Names and labels are trimmed, required, and limited to 100 characters;
landmark IDs are limited to 64 characters. Room names need not be unique.

Connections are undirected: the two rooms can reach one another through the
specified doorway or corridor. Multiple connections between the same rooms are
allowed. Self-connections are not. Every connection endpoint and landmark room
must refer to an existing room. Each collection can contain up to 100 items;
the complete JSON document is limited to 16 KiB. Empty maps are allowed while
being created. Unknown fields, duplicate object keys, duplicate IDs, invalid
references, unsupported schema versions, and invalid connection kinds are
rejected. The server validates the complete document before replacing the
previous saved map.

IDs for maps, rooms, and connections are generated by the browser and remain
stable as names and relationships are edited. Deleting a room requires removing
its connections and landmarks first.

## Caregiver dashboard API

All paths use the existing HTTPS dashboard origin, caregiver login session,
host/origin security boundary, and `Cache-Control: no-store`.

| Method and path | Behavior |
| --- | --- |
| `GET /dashboard/indoor-map` | Authenticated mobile-friendly editor page |
| `GET /dashboard/indoor-map/data` | Returns `{"map": null}` before creation, otherwise the validated map |
| `PUT /dashboard/indoor-map/data` | Accepts a schema-v1 map as `application/json`; requires the editor's CSRF token; validates and atomically saves it |
| `GET /dashboard/indoor-map/export` | Downloads the saved map as `cognisight-home-map.json`; returns 404 if no map exists |
| `POST /dashboard/indoor-map/route` | Accepts saved-map start/destination room IDs as `application/json`; requires the caregiver session and CSRF token; returns a BFS route preview |

Validation errors return HTTP 400 without replacing the prior map. The editor,
data, and export pages/reads require the caregiver session; unauthenticated reads
return 401 (the editor page redirects to login). Invalid or corrupt stored maps
fail closed, and storage failures return an error response without exposing local
paths.

## Route preview

The route planner validates the existing schema-v1 document and treats every
doorway or corridor connection as one unweighted edge. Breadth-first search
returns the shortest room sequence; ties follow connection order in the saved
map. The response includes ordered room `{id, name}` entries and the traversed
connection IDs/kinds. A start equal to the destination returns a one-room route;
disconnected rooms return `status: "unreachable"`. Unknown room IDs are rejected,
and invalid map references/kinds fail schema validation. An empty map has no
valid start room and cannot produce a route.

The caregiver must save map edits before previewing; the endpoint always plans
against the persisted map. The response's `start_source` is
`manual_demo_selection`. The UI labels this input and displays the room sequence
only—there are no coordinates, distances, orientation, left/right turns, camera
localization, or spoken instructions. A route preview does not change the
dashboard's live indoor status.

## Local persistence

The default path is `~/.local/share/cognisight/indoor-map.json`; `cognisight run`
uses the configured private state directory when `--state-dir` is supplied.
The map is not stored in the repository, SQLite profile database, runtime
snapshot, or outdoor navigation state. The file is written with owner-only
permissions using a temporary file and atomic replacement. Keep backups private;
do not place real patient details in room names, labels, or exported files.

## Tests

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_indoor_map*.py' -v
node --test tests/dashboard.test.cjs
```

The web integration tests require the project's existing Flask and Flask-WTF
dependencies. Unit and browser-boundary tests use synthetic map data. No camera,
microphone, hardware, localization, or real-home qualification is performed.
